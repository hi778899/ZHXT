# V7 模型发起界面业务化说明

## 1. 本次调整

V7 将“模型建设界面”和“模型发起界面”进一步分离。模型建设阶段继续保留零代码配置能力；业务使用者进入“可发起模型”后，只看到需要填写和提交的业务内容。

### 设计阶段

- 去除“模型标准表达结构”六列表。
- 同时去除原来的“模型标准表达”说明输入框，避免与真正可执行的运算/公式配置重复。
- 保留表单设计器、模型运行节点、参数定义、运算配置、公式计算、条件规则、测试、数字化库和模型关系配置。
- 新模板的 design JSON 不再写入 `standardSteps`。

### 可发起模型

- 卡片不展示模型原理、归档方式、后续模型关系等解释。
- 只显示业务分类、模型名称和进入入口。

### 模型发起页面

去除以下建设/技术信息：

- “模型运行节点”及节点连线；
- “业务模型运行预览”；
- 模型建设来源与四阶段版本；
- 模型编码、结果数字化库、数字化标识；
- 后续模型和跨模型触发机制；
- “运行界面读取设计阶段字段、服务器执行并写入数字化标识”等实现说明。

保留：

- 模型名称；
- 设计阶段配置的实际业务字段；
- 字段本身面向使用者的业务说明；
- 输入校验提示；

字段数据来源、联动库名称、联动执行状态等实现细节也不在发起页面展示；
- 提交按钮。

## 2. 请休假模型

请休假发起人只填写申请人、所属部门、请假类型、开始日期、结束日期和请假事由等实际字段。请假天数计算、业务归档、数字化标识写入以及归档后触发独立审批模型仍由后台按已发布模型定义执行，但不在发起页面展示。

## 3. 边界

模型内部结构和模型关系仍属于“模型建设工作台”；“可发起模型”属于业务运行入口，两者不混合展示。
