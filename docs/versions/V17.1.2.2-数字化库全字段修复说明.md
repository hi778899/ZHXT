# V17.1.2.2 数字化库全字段修复

本版针对历史数字化库出现“有记录但部分字段为 —”的问题做统一修复，而不是仅针对“请假天数”写死补丁。

## 修复范围

1. 历史输入字段：从 `model_runs.input_data`、历史归档 `data.input`、平铺 `data` 中恢复。
2. 历史输出字段：从 `model_runs.output_data`、历史归档 `data.output` 中恢复。
3. 历史计算字段：按模型设计阶段保存的 `calculations` 重算，支持 `dateDiffInclusive / sum / difference / concat / copy`。
4. 结果数字化标识：按 `outputDigitalMap` 统一写回 `identifier_values`。
5. 旧记录人员/部门：早期记录未保存自动读取字段时，使用记录归属人的姓名、部门、人员编码补齐。
6. 新运行记录：运行引擎会自动把 `outputDigitalMap` 中配置的结果键加入输出，不再依赖用户重复配置 `outputKeys`。
7. 日期计算：改为 UTC 的纯日期计算，避免服务器时区/DST 导致天数偏差。
8. 新增 `016_repair_all_legacy_digital_values.sql`，部署升级时自动回填历史记录；运行时读取数字化库时仍会再次做幂等修复，防止遗漏。

## 请休假示例

开始日期与结束日期相同，`请假天数(5013001005001106)` 自动恢复为 `1`。跨日记录按“结束日期 - 开始日期 + 1”恢复。

本迁移只补齐可由现有历史记录和模型配置确定的数据，不清空、不重建原数据库，也不覆盖已有非空数字化标识值。
