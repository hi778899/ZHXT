# V17.2 数字化库文件化与已办模型簇进度说明

本版在 V17.1.2.4 基础上调整数字化库记录展示和“我的已办”运行关系展示，不改变现有模型运行、数字化入库、审批、智选的核心数据结构。

## 1. 数字化库记录改为文件化展示

数字化库“文件记录”列表不再展开申请人、部门、日期、计算结果等业务数据列，只保留：

- 文件名
- 查看详情

模型每次归档形成的一条数字化库记录，列表中以模型文件名作为唯一业务入口。点击“查看详情”后，继续展示该文件记录中的全部数字化标识、字段值、数据归属、运行信息等内容。

## 2. 我的已办改为模型簇进度

“我的已办”以人工发起的业务模型为根节点组织模型簇，不再把同一事项的审批模型、智选模型分别平铺成多条已办记录。

模型簇关系：

业务模型（根） → 审批模型 → 智选模型

业务模型归档入库后即形成一条已办模型簇记录，并进入“申请阶段”。业务模型行可展开查看审批模型、智选模型是否已启动、当前状态及文件名。

审批模型完成归档后，模型簇进入“有效阶段”。审批模型运行期间和完成后均可在业务模型下展开查看逐级审批进度、审批人、审批结果和办理时间。

智选模型作为审批模型的后续运行节点，在同一模型簇中展示其启动与完成状态。

## 3. 兼容说明

本版不新增数据库表和迁移脚本。模型簇关系直接复用现有 `model_runs.source_run_id`：

- 审批模型 `source_run_id` 指向业务模型运行实例；
- 智选模型 `source_run_id` 指向审批模型运行实例。

因此可直接覆盖升级，保留现有数据库和历史模型运行数据，不需要清库。
