# V17 标准库驱动模型建设与通用审批智选说明

## 1. 本版定位

本版在 V16.1 基础上，将“数字化库既保存模型运行数据、又作为标准数据源”的理念进一步落到模型建设与运行内核。核心规则是：可选择的数据优先从对应模型数字化库读取，避免在业务模型内重复维护固定下拉项。

## 2. 标准库就是对应模型运行形成的数字化库

- 每个标准数据集合都有对应模型；模型运行归档后形成数字化库记录。
- 下拉、单选、多选、人员、部门等选择类字段必须配置“数字化库 + 16位数字化标识”作为来源。
- 多个字段可以复用同一个标准库，例如申请人、审批人、参会人都可以读取人员信息标准库。
- 数字化库列继续使用 16 位数字化标识作为系统识别字段，并显示中文名称。

## 3. 四个建设阶段是真正的四个建设模型

模型建议模型、模型设计模型、模型测试模型、模型配置模型均可独立进入和保存草稿，不再因为前一阶段未归档而整页灰掉。真正归档和进入下一阶段时仍按建设链校验前序 M→A→S 闭环。

已发布模型需要调整时，使用“修改模型（新轮次）”，生成新的建设轮次并保留旧版本，不需要修改程序代码。系统初始化只维护版本 1 的基线模板，用户形成新版本后不会在重启时被种子数据覆盖。

## 4. 基础标准模型/库

本版建立并接入人员、部门、请假类型、模型信息、数字化类型、数字化编码类型、业务层级、数字化定义类型、数字化对象类型、数字化属性定义、数据类型、组织性质、组织职级、行政审批层级、业务审批层级、审批意见、阈值类型、会议类型、会议室、议题审定意见、是否、模型时限等基础标准模型/库。

同时建立数字化配置、数字化展示、行政审批层级分选、业务审批层级分选、岗位分选、标识触发配置、业务归属、审批分管、审批阈值等配置模型/库。

## 5. 通用审批模型

审批模型不保存请假、会议等业务专属字段。运行时优先读取标准数字化库配置，根据前序业务事项查找行政审批层级、业务审批层级和岗位分选结果，动态形成审批步骤；审批意见也从审批意见标准库读取。旧版固定步骤只作为历史数据兼容兜底。

当前请休假基线示例由标准配置记录给出：行政审批由部门经理办理，业务审批由考勤主管办理。后续可直接运行相应配置模型修改，不需要改代码。

## 6. 通用智选模型

智选模型读取原业务模型文件名、数字化标识及数字化配置，并查询“标识触发配置标准库”。存在关联记录时形成目标模型集合并逐一触发；不存在关联时形成“本模型没有后续关联模型”的结果。目标关系由配置模型的数据决定，不在智选模型代码里逐个维护业务模型。

## 7. 数据录入原则

模型应用默认遵循：标准库选择 > 数据联动 > 当前用户自动识别 > 系统计算 > 人工填写。真正的新业务事实才由人员输入。

## 8. 数据库升级

新增 `014_model_backed_standard_libraries.sql`：建立标准/配置模型、数字化标识与数字化库列，写入首批系统初始化基线标准数据，并把既有选择类字段迁移为数字化库数据源。初始化基线后，业务人员应通过相应标准模型新增或调整数据。
