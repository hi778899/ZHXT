# V12：智选模型进入发起人待办

## 运行关系

请休假模型归档 → 审批模型 → 行政审批 → 业务审批 → 审批模型归档 → 智选模型自动运行 → 判断是否触发新的业务模型。

智选模型仍然是自动模型，不增加人工审批节点或人工判断步骤。为了让原业务发起人能够看到系统已经进行了智选，本版本在智选完成后给原业务发起人生成一条“智选结果”待办，状态为“待确认”。

## 待办展示

智选结果待办展示：

- 业务来源；
- 原业务申请内容；
- 审批结果；
- 智选判断；
- 实际触发的后续模型；
- 后续模型触发异常（如有）。

如果没有匹配到后续业务模型，明确显示“未触发新的业务模型”。

该待办只有“确认已查看”，不会让发起人重新决定智选结果。确认后记录进入“我的已办”。

## 人员归属

智选结果待办归属于原业务模型的发起人。例如张珊发起请休假，审批模型完成后触发智选模型，则智选结果显示在张珊的“我的待办”中，不会错误显示在部门经理或考勤主管的待办中。

## 兼容历史数据

新增迁移 `009_smart_model_todo_visibility.sql`。已有已归档智选模型运行记录如尚无对应待办，将补生成“智选结果”待确认记录，并尽量根据子模型运行记录恢复已触发的后续模型名称。
