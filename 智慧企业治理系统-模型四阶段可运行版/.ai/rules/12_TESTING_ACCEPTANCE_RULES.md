# 12 测试与验收规则

## 1. 测试层级

至少覆盖：

- 单元测试
- API/服务测试
- 数据库 migration 测试
- 模型运行集成测试
- 审批集成测试
- 智选集成测试
- 关键 E2E
- 生产构建验证

## 2. 模型建设核心验收

必须验证：

1. 四阶段均可编辑并持久化；
2. 可从旧版本创建新草稿修改；
3. 发布后产生可运行模型；
4. 发布后建立对应数字化库；
5. 需要选择既有数据的字段能从指定数字化库动态加载；
6. 业务模型运行后正确写入本模型对应数字化库；
7. 入库后自动进入审批；
8. 审批完成后自动进入智选；
9. 智选按标识触发正确后续模型；
10. 全链路可通过“数字化编码 + 模型文件名 + 来源模型文件名”追溯；
11. 系统不得依赖模型 ID/实例 ID 识别模型或串联模型簇。

## 3. 回归测试

修改公共模型引擎、审批、智选、数据源或数字化配置时，必须回归至少一个既有已发布模型，防止平台改动导致历史模型失效。

## 4. 负面测试

必须考虑：

- 所引用数字化库不存在或不可用
- 标识无关联模型
- 审批不同意
- 重复提交
- 权限不足
- 数据源不可用
- migration 失败
- 模型版本不兼容
- 循环触发
- 重复定量触发

## 5. 验收证据

重要需求应保留测试日志、CI 结果、接口结果或界面截图，不能只以“开发人员说能用”作为验收依据。
