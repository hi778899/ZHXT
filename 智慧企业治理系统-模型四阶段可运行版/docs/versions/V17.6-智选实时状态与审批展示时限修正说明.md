# V17.6 / 18.3.6.1 修正说明

## 一、智选关联状态实时一致

已办、办结和业务详情不再只依赖旧的单一 `source_run_id` 快照关系。服务端会结合真实运行引用、来源模型文件名、业务模型文件名以及智选待办事实解析关联模型。只要智选模型已经形成真实运行或待办，就不能显示“未启动”。

状态显示统一为：

- 已归档/已完成/已办结：`已完成`；
- 已存在运行或待办：`运行中`；
- 只有不存在真实运行、待办、归档事实时：`未启动`。

## 二、审批模型普通界面显示边界

后台继续完整保存审批路径和审批人计算留痕，但普通用户界面隐藏以下技术字段：

- 审批路径计算依据；
- 正式审批路径节点；
- 审批人计算依据；
- 审批人计算区域中的本环节审批/审查要求；
- 审批办理记录中的审批人计算依据、审批路径计算依据。

不删除后台运行数据，不影响审计和后续模型运算。

## 三、规定时限

规定时限从模型时限数字化库读取并展示实际值。0622数据只定义数值8、16，没有定义单位，因此前端只显示 `8`、`16`，不得显示“8小时”“8天”等。

对0622中同一业务同时命中多条时限配置的情况，后端优先采用适用业务范围更具体的配置；同一优先级仍存在多个不同值时返回“未配置”，不擅自取最大或最小。历史运行记录中如保存了无法唯一解释的复合时限值，界面同样显示“未配置”。

## 四、数据库

本版不新增数据库迁移，继续使用现有020数据。
