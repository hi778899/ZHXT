# V17.4 通用审批计算与已办办结阶段追溯说明

对应代码包：18.3.5 / V17.4。

## 一、本版目标

本版落实 V17.4 已确认规则：恢复“申请阶段 / 有效阶段”作为业务模型在审批链中的阶段语义；已办和办结均可从业务模型直接追溯并打开审批模型、智选模型本身；审批模型作为全系统共用模型，动态承载任意来源业务模型；审批路径、审批人员、办理要求和规定时限均由数字化属性、数字化标识及相关数字化库配置计算。

## 二、已办与办结

- 业务模型完成并写入自身数字化库后进入申请阶段。
- 审批模型完成且结果通过后，业务模型进入有效阶段。
- 审批终止或不通过时显示“审批终止/未生效”，不得显示有效阶段。
- 我的已办中的业务模型可展开关联模型，也可在业务模型详情中继续直接打开审批模型和智选模型。
- 我的办结按单模型完成口径记录；业务模型即使下游模型仍在运行，也属于已办结模型，同时保留当前申请/有效阶段和关联模型入口。
- 点击审批模型或智选模型时进入该次模型运行详情，不进入独立的模型簇进度页面。

## 三、通用审批业务内容

审批模型不包含请假、采购等具体业务页面。每次运行根据来源业务模型运行记录读取来源项目、模型设计字段、模型数字化编码、数字化标识和值，并形成 `approvalBusinessContent`。审批办理页和审批模型详情按来源字段元数据动态渲染业务内容，因此新建其他业务模型后无需新增审批页面。

## 四、审批计算

审批模型先读取来源业务模型的数字化属性和数字化标识，再计算基础审批目标 T，并按金额、天数、人员、风险、上报、上会等阈值形成调整后目标 T′。审批路径从申请人所在组织开始，进入新的上级或分管组织后重新读取该组织自己的组织职级和人员配置。技术/业务审查路径独立计算后与行政审批路径合并，并按实际人员去重。

每个审批节点携带：办理要求、规定时限、提醒规则、输出字段和计算依据。待办创建时根据该节点规定时限计算到达时间和到期时间；审批模型详情展示来源业务、T/T′、组织路径、命中阈值、正式审批路径以及各节点办理记录。

## 五、兼容性

- 未新增数据库表或字段，本版不新增 migration。
- `lib-standard-*` 等历史技术 ID 继续保留，仅作为兼容标识，不作为用户界面中的库分类概念。
- 旧审批模型的兜底步骤继续兼容，但新审批运行优先使用数字化库配置。
- 历史“考勤主管”只作为旧配置兼容角色，不再作为通用业务审批的默认人员。
