# V17.7 驾驶舱主流工作台布局与名称修正说明

## 1. 修订目标

将驾驶舱从概念性分类结构调整为成熟企业软件常见的工作台结构。用户界面不再展示抽象的人机关系分类标题，统一使用直接表达操作和信息内容的业务化名称。

## 2. 当前页面结构

驾驶舱首页当前统一为：

1. 工作台页头；
2. 快捷入口；
3. 我的事项；
4. 工作概览；
5. 常用服务。

系统模块仍可称“驾驶舱”，普通用户首页使用“工作台/个人工作台”作为页面名称。

## 3. 快捷入口

当前包括：

- 发起业务：进入本人有权使用的已发布模型；
- 模型建设：进入业务定义、数字化定义、模型设计、模型发布四阶段建设。

## 4. 我的事项

统一保留：

- 我的待办；
- 我的已办；
- 我的办结；
- 待办事项列表。

待办、已办、办结的既有数据定义不变。

## 5. 工作概览

统一展示：

- 今日办结；
- 今日工作记录；
- 今日已办理；
- 排名。

所有统计继续由后端读取真实模型运行、数字化库和办理记录计算。

## 6. 常用服务

当前包括：

- 数字化库；
- 公共信息；
- 可发起模型。

只允许显示系统真实存在且当前用户有权限的入口。

## 7. 规则影响

`.ai/rules/18_DASHBOARD_RULES.md` 已重写为 V17.7 当前有效规则，历史概念性驾驶舱分组不再作为新功能设计、代码实现或验收依据。

本次不修改待办、已办、办结、审批、智选、模型运行和数据库结构，仅调整驾驶舱的信息架构、用户界面名称及对应回归约束。
