# V15 数字化库统一与通用审批、智选说明

## 1. 主界面入口收敛

- 删除“数据查询”：数据查询与数字化库都面向已形成数据的查看，V15 统一由“数字化库”承接。
- 删除“工作信息”：个人工作处理统一进入“我的待办”，不再保留重复入口。
- 主导航保留：驾驶舱、数字化库、我的待办、我的已办、模型建设、公共信息、管理后台（管理员）。

## 2. 数字化库以模型配置和实际入库记录为准

“数字化库”不再依赖是否已经产生过运行数据来决定库是否显示，而是读取每个模型第4阶段配置的 `storageName`、16位模型数字化编码和16位数字化标识。

因此当前应用中的“请休假模型数字化库”“审批模型数字化库”“智选模型数字化库”等，即使记录数为0，也会显示在数字化库列表中。

模型每次运行完成后，把实际运行结果写入 `digital_library_records`，核心数据库字段：

- `id`
- `model_id`
- `project_id`
- `run_id`
- `owner_id`
- `library_name`
- `digital_id`
- `data`（JSONB，保存本次模型实际入库内容）
- `created_at`

前端“数字化库”直接按上述数据库记录查看，不再额外维护一份 `query_records` 查询副本。

管理员可查看全部数字化库记录；普通用户查看本人可见的运行记录。数据联动接口仍按运行权限读取数据源。

## 3. 业务模型数字化库

业务模型自己的数字化库保存该模型的实际运行内容：

- 系统文件名
- 中文显示名称
- 16位数字化标识
- 本次输入 `input`
- 本次运算/规则结果 `output`
- `runId`

不同业务模型拥有各自独立的模型·库和数据结构。

## 4. 审批模型保持通用

审批模型面向所有业务模型，不在审批模型设计中固化“请假类型、请假天数、采购金额”等任何业务专属字段。

审批模型数字化库只保存通用审批运行数据，例如：

- 前序业务模型名称
- 前序业务模型文件名/中文名称
- 前序业务数字化标识
- 前序运行 `runId`
- 审批路线
- 审批状态
- 审批结果
- 审批过程（步骤、办理人、意见、时间）

审批人员办理时仍可根据当前前序运行上下文动态查看该业务的具体内容，但这些内容不写死进审批模型的建设模板和固定数据结构。

## 5. 智选模型保持通用

智选模型同样面向所有业务模型，不在智选模型内维护“业务模型A→目标模型X、业务模型B→目标模型Y”这样的全系统目标清单。

业务模型自己的第4阶段可以配置“智选关联（审批后判断）”：

- 当前业务数字化标识
- 判断数据/参数
- 条件
- 目标业务模型

标准运行关系：

`业务模型归档 → 硬性链接审批模型 → 审批模型归档 → 硬性链接智选模型 → 智选读取原业务模型自己的智选关联 → 判断是否启动新的业务模型`

智选模型数字化库只保存通用关联结果：

- 原业务模型名称
- 原业务系统文件名/中文名称
- 原业务16位数字化标识
- 关联数字化标识集合
- 关联目标模型集合
- 审批结果
- 智选判断结果

这样业务模型数量增加时，不需要修改审批模型或智选模型本身。

## 6. 数据库迁移

新增 `server/migrations/012_digital_library_and_generic_control_models.sql`：

- 停用历史“数据查询模型”；
- 业务模型补齐“硬性链接→审批模型”的固定关系；
- 审批、智选模板清理为通用对象字段；
- 已有审批/智选数字化库记录收敛为通用字段；
- 删除已废弃的 `query_records` 表，数字化库成为模型运行数据的唯一查看入口。
