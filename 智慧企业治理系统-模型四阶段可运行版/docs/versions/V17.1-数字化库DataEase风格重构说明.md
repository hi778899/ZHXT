# V17.1 数字化库 DataEase 风格重构说明

本版本在 V17 标准库驱动与可配置审批/智选基础上，仅重构数字化库展示与交互层，并合并 014 数据库迁移的 PostgreSQL 歧义列修复。

## 1. 数字化库界面

- 左侧改为数字化库目录，支持全部/标准库/模型库筛选和搜索。
- 右侧采用“库概览 + Tab”结构，参考 DataEase 数据集的目录、数据预览、字段管理思路。
- Tab 包含：数据记录、字段设计、模型关联、权限。
- 数据记录列表采用双层表头：第一行显示中文业务字段名，第二行显示对应 16 位数字化标识。
- 数字化标识始终保留显示，并继续在字段设计、模型关联和单条记录详情中完整展示，用于技术配置、跨模型引用与智选核验。
- 记录值读取增加兼容：优先读取 identifier_values；旧数据若只在 data 中文字段中保存，也能正常展示，减少页面出现整列“—”。
- 表格支持横向滚动、固定记录列、当前库内搜索。

## 2. 字段设计说明

字段设计页明确显示：
- 字段中文名称；
- 数据类型；
- 是否必填；
- 字段角色；
- 16 位数字化标识。

选择类字段继续遵循“数字化库 + 数字化标识”数据源机制；多个下拉字段允许复用同一标准数字化库。

## 3. 模型关联与权限

- 模型关联页显示数据产生模型、数字化库以及各字段可引用状态。
- 权限页按照服务端现行规则说明普通用户、管理员和模型引用权限。
- 本版本不改变四阶段模型建设、审批模型、智选模型核心运行逻辑。

## 4. 部署修复

修复 `014_model_backed_standard_libraries.sql` 中 PostgreSQL `42702 ambiguous_column`：
- `name` 改为 CTE 专用字段 `type_name` / `attr_name`；
- `description` 改为 `attr_description`。

因此新部署或旧数据库继续迁移时，不需要手工再次修改这两处 SQL。
