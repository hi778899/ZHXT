# V14：16位数字化编码、系统文件名与中文显示名称

## 1. 编码规则

本版本按当前确认口径统一执行：

- 模型数字化编码：16位数字；
- 人员数字化编码：16位数字；
- 数字化标识：16位数字；
- 系统文件名：`模型数字化编码-发起人人员数字化编码-时间码`；
- 时间码：`YYYYMMDDHHmmss`，默认使用 `Asia/Shanghai` 业务时区；
- 中文显示名称：`模型中文名称-发起人姓名-时间码`。

请休假模型示例：

- 模型数字化编码：`5011001005001002`；
- 张珊人员数字化编码：`5011002000000001`；
- 请休假模型数字化标识：`5013001005001002`；
- 系统文件名：`5011001005001002-5011002000000001-20260908140000`；
- 中文显示名称：`请假模型-张珊-20260908140000`。

系统文件名用于模型传递、运行追踪和数据关联；中文显示名称用于“数据查询”“智选结果”等面向用户的界面。

## 2. 内置账号人员数字化编码

首次部署或升级后：

- 张珊：`5011002000000001`；
- 部门经理：`5011002000000002`；
- 考勤主管：`5011002000000003`；
- 其他已有人员：迁移时按创建顺序从 `5011002000000004` 开始分配；
- 后续审核通过的新账号：系统按同一16位规则自动顺序生成。

管理后台“用户管理”中会显示人员数字化编码。

## 3. 智选模型显示与判断

智选模型保留最初业务模型的信息，不把审批模型自身文件名当成业务对象。智选结果中明确保存并显示：

- 业务模型；
- 文件名（系统文件名）；
- 中文显示名称；
- 数字化标识；
- 关联数字化标识；
- 审批结果；
- 智选判断；
- 后续关联模型。

当前请休假模型没有配置智选后续关联模型，因此：

- 文件名：使用最初请休假模型的系统文件名；
- 中文显示名称：例如 `请假模型-张珊-20260908140000`；
- 数字化标识：`5013001005001002`；
- 关联数字化标识：`无`；
- 智选判断：`本模型（请休假模型）没有后续关联的模型`；
- 后续关联模型：`无`。

“请休假模型 → 审批模型 → 智选模型”仍属于已经配置的模型运行关系，其中请休假归档触发审批、审批归档触发智选属于硬性链接；它们不等同于智选模型判断得到的“后续关联业务模型”。

## 4. 四阶段配置校核

模型建设第4阶段现在强制校核：

1. 模型数字化编码必须为16位数字；
2. 数字化标识必须为16位数字；
3. 模型发布后运行文件名由系统自动生成，用户不再手工维护 `FN-` 前缀；
4. 跨模型传递同时保留系统文件名、中文显示名称和数字化标识。

## 5. 数据库升级

新增迁移：`server/migrations/011_16_digit_codes_and_display_filename.sql`。

迁移会：

- 为用户补充分配16位人员数字化编码；
- 为模型运行记录增加中文显示文件名；
- 把内置模型的模型数字化编码和数字化标识切换为16位；
- 将已有模型运行文件名转换为新格式；
- 同步更新数字化库记录、查询记录和智选待办中的文件名/数字化标识；
- 保留已有业务数据、审批过程和模型关系，不清空数据库。
