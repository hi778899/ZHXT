# V17.3.1 办结审批详情、部门联动与数字化库统一说明

## 1. 修复范围

本版本在 V17.3 基础上修复三个问题：

1. 驾驶舱“我的办结”中点击审批模型后空白；
2. 请休假模型发起时“所属部门”未自动显示当前人员所在部门；
3. 页面仍存在“标准库/非标准库”分类概念，与现行数字化库规则冲突。

## 2. 我的办结审批模型

删除办结详情中已经废止的模型簇进度解析入口。审批模型、智选模型均按独立模型运行文件直接打开自身详情。服务端办结数据同时按模型名称识别审批模型、智选模型运行类型，兼容历史项目缺少 modelType 的情况。

## 3. 请休假所属部门

请休假模型的申请人继续使用当前登录人员；所属部门优先直接使用当前登录人员账户中的部门信息，同时保留“人员信息数字化库”联动，由数字化库匹配结果覆盖。

新增迁移 `018_unify_digital_library_naming_and_leave_department.sql`，对既有已发布请休假模型补齐 `library_fill` 配置，确保历史生产库无需清库即可升级。

## 4. 数字化库统一

系统对外只使用“数字化库”概念，不再向用户展示“标准库/非标准库”分类。数字化库是否允许被其他模型引用仅作为“允许作为数据源”的能力配置，不构成新的库类型。

历史 `lib-standard-*` 仅作为兼容技术 ID 保留，不作为用户界面概念。

## 5. 数据迁移

升级时执行 018 增量迁移，统一既有数字化库显示名称、历史模型配置中的库名称，并修复请休假部门联动。不得删除现有数据库卷。
