# 10 AI 辅助开发规则

## 1. AI 的角色

AI 是研发执行者和辅助分析者，不是项目事实来源。项目事实来源依次为：用户明确要求、根目录规则、Git 当前代码、数据库 migration、自动测试和正式文档。

## 2. 开发前必须执行

1. 拉取/读取最新目标分支；
2. 阅读根目录规则；
3. 搜索已有实现和公共组件；
4. 分析影响范围；
5. 明确预计修改文件；
6. 检查相关测试；
7. 再进行修改。

## 3. 修改原则

- 最小必要修改；
- 优先复用已有机制；
- 不顺手重构无关模块；
- 不重新生成整个项目覆盖现有代码；
- 不删除旧功能以规避冲突；
- 不通过 mock 假装真实功能完成；
- 不把数据库数据改成静态常量；
- 不为了修页面绕开模型运行引擎；
- 不直接修改 main。
- 不新增 `model_id`、模型 ID、实例 ID 等业务身份机制；模型唯一性必须使用数字化编码，运行记录必须使用模型文件名。

## 4. 当规则不明确时

先通过代码、Git 历史和既有文档确认；若仍存在关键歧义，应在变更说明中明确假设，不得悄悄自行改变核心架构。

## 5. 完成标准

“代码已写完”不等于完成。至少需要：

- 编译/构建成功；
- 类型检查通过；
- 相关测试通过；
- Git diff 无意外删除；
- migration 已验证；
- 业务验收条件可执行；
- 变更说明完整。

## 6. 禁止伪完成

不得声称“已修复/已完成”，除非有实际代码变化和验证证据。若当前环境无法执行测试，应明确写出“未验证项”。
