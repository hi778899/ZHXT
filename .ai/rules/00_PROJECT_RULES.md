# V17.7.18 当前增补——审批完整路径执行与归档判定

1. 审批模型的完成判定必须以最终审批路径 `Path_final` 的执行状态为唯一依据，不得以行政审批子路径是否达到 `A_final` 作为审批模型完成条件。

6. 正常同意路径只有在 `Path_final` 全部必经节点完成后，才允许形成最终审批结果、写入审批模型数字化库并触发智选模型。
7. “不同意/终止”属于终止型结果；命中正式终止规则时可以提前结束剩余路径，但仍必须形成最终审批结果并归档，随后按系统硬性链路触发智选模型。

# V17.7.8 当前增补——模型簇硬性触发与失败可见性

1. 需要审批的业务模型正式写入本模型数字化库后，系统必须启动通用审批模型；该关系属于系统硬性链接，不以业务模型历史 `relations`、`afterArchiveEnabled`、`nextModelName` 是否完整为成立条件。
2. 审批模型的“启动”先于基础行政审批级次、最终行政审批级次、技术/业务审查级次和正式路径计算。系统收到业务数字化库的硬性触发后，应先建立真实审批模型运行实例，再在该实例内部读取各数字化库并执行相对级次和路径计算。
3. 审批目标或审批路径计算失败时，不得表现为“审批模型未触发”。审批运行实例应保留并标记为“运行异常”，记录缺失的数字化库配置或其他失败原因。
4. 业务模型已经归档但审批模型未成功形成运行实例时，不得向用户返回普通“提交成功”；必须返回明确的模型簇触发异常，并形成失败记录。
5. `业务模型 → 业务数字化库 → 审批模型 → 审批数字化库 → 智选模型` 是模型簇统一链路。业务→审批与审批→智选均由运行引擎提供系统级兜底，不允许历史模型配置缺失造成断链。

# 00 项目总规则

## 1. 系统定位

智慧企业治理系统是以“模型·库”为基本运行颗粒构建的企业治理平台。系统中的审批、会议、请休假、驾驶舱、人员信息、数字化配置等能力，原则上均通过统一的模型建设、数字化配置和模型运行机制形成，而不是为每个业务单独堆叠不可复用的页面与代码。

## 2. 最高级业务原则

### 2.1 一模型一数字化库

每个模型必须且只能对应一个本模型数字化库。模型运行形成的有效结果，只能写入该数字化库。

### 2.2 模型簇

需要治理流转的业务模型，统一通过模型簇运行：

`业务模型 → 审批模型 → 智选模型 → 关联业务模型`

其中：

- 业务模型完成运行并将正式结果写入本业务模型对应数字化库后，由该数字化库按硬性链接规则触发审批模型，并传递业务模型文件名；
- 审批模型完成运行并将审批结果写入审批模型对应数字化库后，由该数字化库按硬性链接规则触发智选模型，并传递审批模型文件名；
- 智选模型读取业务结果、审批结果和数字化关联规则，确定后续需要启动的模型运行；每次被启动模型运行均生成自己的模型文件名。

### 2.3 数字化三要素

系统数字化表达统一围绕：

- 数字化编码：确定模型及数字化对象身份与唯一性；系统不另设模型 ID；
- 属性：描述对象类别、特征和计算所需属性；
- 标识：表达有效运行结果、状态和关联触发条件。


### 审批界面展示总原则（V17.7.16）

1. 组织数字化库中的组织数字化属性用于内部对应和计算审批/审查级次，并与组织关系、审批分管配置、员工信息共同确定实际人员。
2. 普通审批界面不得显示基础审批目标、最终审批目标、基础/最终行政审批级次、技术/业务审查目标层级或级次、组织逐级路径、组织数字化属性匹配过程、命中数字化标识阈值及其他中间运算过程。
3. 普通审批界面只显示运算后的最终审批路径 `Path_final`。
4. 最终路径节点统一显示为“岗位/角色名称（员工数字化编码）”，例如“部门经理（50110020015）-考勤主管（50110020023）”。
5. 中间计算字段仍须在模型内部和数字化库中保存，用于审计和问题追溯；界面隐藏不等于删除数据。

当前数字化结构按对象分别编码：模型19位、员工11位、业务分类属性19位、数字化标识19位、组织数字化属性12位、组织名称数字化属性12位；具体结构以 `04_DIGITALIZATION_RULES.md` 当前有效规则为准。

> 【历史口径已作废】原“统一16位数字化结构”仅用于历史数据兼容，不再约束新建数据。

### 2.4 四阶段模型建设

模型必须通过四个建设模型逐级形成：

1. 业务定义模型
2. 数字化定义模型
3. 模型设计模型
4. 模型发布模型

这四个阶段不是四个页面步骤，而是四个可运行的建设模型。每个建设模型自身同样遵循“一模型一数字化库”，并按“建设模型 → 审批模型 → 智选模型”的模型簇完成本阶段确认与下一阶段触发。四个建设模型均必须在系统中可填写、可保存、可恢复、可修改、可追溯。不得要求用户每次修改目标模型都重新修改源代码。

### 2.5 所有可选数据均来自数字化库

系统所有模型对应的库统一称为“数字化库”，不另设其他库分类。凡出现下拉框、单选、多选、人员选择、部门选择、会议类型、审批层级等需要引用既有数据的字段，默认必须从相应模型运行形成的数字化库读取。多个字段、多个模型可以共享读取同一数字化库，但不得复制数据形成另一套静态枚举。

### 2.6 模型业务数据以对应数字化库为唯一正式来源

模型运行形成的业务字段、审批结果、智选结果、统计结果以及其他正式业务数据，必须从该数据归属模型的数字化库读取。`model_runs`、`run_id`、模型文件名、待办/已办记录只用于定位运行、标识状态、关联上下游和审计追溯，不得替代数字化库成为业务字段的正式展示来源。规定时限等配置型数据同样读取其归属数字化库，例如审批规定时限读取“模型时限数字化库”。

### 2.7 审批/审查级次统一采用相对流程级次

系统内所有进入通用审批模型的模型，行政审批、技术审查、业务审查均以本次发起人为起点采用相对流程级次。

- 第一个有效行政审批节点 = 一级审批；第二个 = 二级审批，依次类推；
- 第一个有效技术审查节点 = 一级技术审查；
- 第一个有效业务审查节点 = 一级业务审查；
- 行政审批、技术审查、业务审查分别独立编号。

“三级机构、四级机构、五级机构”等属于组织数字化属性，只用于组织路径、岗位和人员匹配，不等同于审批级次。

统一计算关系：

`来源模型 → 基础行政审批级次 A_base → 阈值/特殊属性调整 → 最终行政审批级次 A_final → 相对行政审批路径`

技术审查和业务审查分别按自己的目标相对级次独立生成路径，再按模型路径配置合并。

例如员工请休假：

`员工发起 → 一级审批：部门经理 → 一级业务审查：考勤主管 → 办结`

不得再以“五级机构·正职/负责人 → 四级机构·正职/负责人”表示基础/最终审批目标。完整规则见 `20_APPROVAL_RELATIVE_LEVEL_RULES.md`。

## 3. 平台与业务的边界

平台代码负责：

- 模型建设器
- 表单/界面设计器
- 数字化配置器
- 模型运行引擎
- 审批引擎
- 智选引擎
- 数据源引擎
- 权限体系
- 审计体系
- 数据库迁移
- 发布运行机制

业务模型配置负责：

- 字段
- 界面
- 规则
- 数据来源
- 数字化标识
- 审批关联
- 智选关联
- 触发方式
- 输出内容

除平台能力不足需要扩展平台机制外，新增一个普通业务模型不应要求复制一整套新的前后端代码。

## 4. 修改原则

- 采用增量修改，不重写整个项目。
- 先复用已有通用能力，再增加新能力。
- 只修改本需求必要范围。
- 保持历史已发布模型可运行。
- 数据结构变化必须可迁移、可回滚或有明确回退策略。
- 模型定义与模型运行数据分离。
- 草稿配置与已发布版本分离。

## 5. 规则文件优先级

本文件是业务规则总纲；专项规则对具体领域具有更高约束力，但不得与本总纲冲突。

## 6. 当前专项规则索引

审批模型内部逻辑必须同时遵守 `17_APPROVAL_MODEL_INTERNAL_LOGIC_RULES.md`；驾驶舱、待办、已办、办结和个人统计必须同时遵守 `18_DASHBOARD_RULES.md`。其他规则索引见本目录 `README.md`。

## V17.7.12 模型文件名全量统一规则

模型文件名统一采用 `模型数字化编码-发起/运行人员员工数字化编码-时间码`。该规则同时适用于新运行、升级时仍在运行的数据以及既有数字化库运行记录。既有旧格式文件名必须通过 migration 转换为新格式，并同步更新来源模型文件名、审批/智选关联、待办已办办结、驾驶舱和审计链路引用。旧文件名只能作为迁移审计映射保存，不得继续作为现行业务链路键。

## V17.7.14 数字化库记录必须由模型运行形成

“一模型一数字化库”同时约束数据形成机制，而不仅是库名称对应关系。所有正式 `digital_library_records` 记录必须具有对应的真实 `model_runs` 运行记录和非空 `run_id`。业务数据、审批数据、智选数据，以及员工、组织、模型时限、审批分管、业务定义、数字化定义、数字化标识等基础/配置数据均不得例外。

系统初始化和系统同步不是“直接写库”的例外，而是对应数据产生模型的特殊运行方式：先形成 `system_initialization` 或 `system_sync` 模型运行，再以该运行文件名归档到对应数字化库。`std-*`、`src0622-*`、`auto0622-*` 等历史技术键只能作为 `legacy_record_id` 审计信息，不得作为文件名、运行身份或模型簇链路键。
