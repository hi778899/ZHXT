# 19 模型簇业务-审批-智选硬性触发规则

> 当前有效版本：V17.7.8

## 1. 固定主链

`业务模型 → 业务模型数字化库 → 审批模型 → 审批模型数字化库 → 智选模型`。

业务→审批、审批→智选均为系统硬性链接。配置关系用于可视化、追溯和发布校验，但不是硬性链接成立的唯一条件。

## 2. 业务→审批

业务模型只有在业务结果已经有效写入对应数字化库后才触发审批。触发主体是完成有效入库的数字化库/运行引擎，不允许业务模型在入库前直接创建审批节点或审批待办。

触发后必须先形成审批模型运行实例。审批运行实例形成后，审批模型再读取数字化库执行审批目标、审批人、阈值、时限和路径计算。

## 3. 审批→智选

审批模型形成正式最终结果并写入审批数字化库后，无论最终结果为同意、不同意或其他正式终止结果，均启动智选模型。是否继续启动后续业务模型，由智选模型判断。

## 4. 失败与状态

- 业务已归档但审批运行实例未创建：业务提交不得显示普通成功，记录硬性触发失败。
- 审批运行实例已创建但内部计算失败：审批模型显示“运行异常”，保留具体数字化库配置错误。
- 审批已归档但智选未创建：记录审批→智选硬性触发失败。
- 所有失败均不得静默吞掉。

## 5. 发布校验

业务模型发布时应显示系统固定“归档后启动审批模型”；审批模型发布时应显示系统固定“归档后启动智选模型”。二者不得作为普通可删除关系。

## 6. 请休假模型

请休假模型不具有专用审批流程。请休假模型完成自身数字化库归档后，由系统固定业务→审批关系启动通用审批模型；审批模型再依据正式数字化库数据动态计算本次审批。
