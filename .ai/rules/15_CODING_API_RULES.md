# 15 编码与 API 规则

## 1. 通用编码原则

- 单一职责；
- 明确类型；
- 避免巨型文件；
- 公共逻辑复用；
- 业务规则不散落在 UI；
- 错误不静默吞掉；
- 模型关联使用数字化编码，模型运行记录关联使用模型文件名；不得新增模型 ID/实例 ID 作为业务唯一性依据。

## 2. 前端

前端主要负责展示、交互和调用，不应成为审批、智选、模型发布的最终规则执行中心。

表单组件必须支持统一的数据源协议，以便绑定任一被授权读取的数字化库。

## 3. 后端

后端负责：

- 权限校验
- 模型定义校验
- 业务事务
- 数字化映射
- 模型运行
- 审批/智选执行
- 持久化
- 审计

## 4. API

API 应：

- 版本清晰；
- 使用一致错误结构；
- 参数校验；
- 权限校验；
- 模型接口返回数字化编码；运行相关接口返回本次模型文件名及必要的来源模型文件名；
- 支持幂等场景；
- 关键操作有 traceId。

## 5. 模型定义接口

模型建设相关 API 应区分：

- 草稿保存
- 阶段校验
- 版本查询
- 发布校验
- 正式发布
- 运行
- 停用/归档

禁止通过一个“save”接口同时隐式完成所有阶段且不可追踪。

## 6. 错误处理

错误至少区分：

- 参数错误
- 权限错误
- 配置错误
- 数据源错误
- 模型定义错误
- 运行错误
- 审批错误
- 智选错误
- 数据库错误

面向用户返回可理解信息，日志保留技术细节。
