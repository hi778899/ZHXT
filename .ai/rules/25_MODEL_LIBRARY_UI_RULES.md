# 25 模型库界面与统一目录规则

> 当前有效版本：V17.7.25
> 适用范围：驾驶舱模型库入口、模型库页面、模型/数字化库目录与详情展示。

## 1. 名称口径

1. 驾驶舱、顶部导航、面包屑及相关统一入口原显示名“数字化库”统一改为“模型库”。
2. “模型库”是前端统一查询与查看入口，不改变底层“一模型一数字化库”架构，也不取消“数字化库”这一正式技术/业务概念。
3. 具体某一个库的名称、字段数据源、模型存储位置等仍使用“数字化库”称谓，例如“员工信息数字化库”“模型时限数字化库”。

## 2. 模型库页面范围

模型库页面必须同时覆盖：

- 系统中的全部模型；
- 系统中的全部数字化库。

“全部模型”不得通过当前数字化库列表反向推导，必须直接读取系统模型目录，确保尚未形成库、不可人工发起、系统内置或配置类模型仍可被查看。

“全部库”读取全部有效数字化库，并继续执行现有记录权限控制。

## 3. 页面一级入口

模型库中心只保留两个一级入口：

1. `全部模型`
2. `全部库`

禁止增加以下一级入口或同义入口：

- 模型分类查看；
- 库分类查看；
- 模型库关联查看。

页面可以搜索当前范围，但不得要求用户先按分类进入不同页面。

## 4. 全部模型

全部模型列表至少显示模型名称、模型类别和运行记录数量，并支持按模型名称、模型类别、模型数字化编码及对应库名称搜索。

点击模型后至少展示：

- 模型名称；
- 模型类别；
- 模型数字化编码；
- 发布/系统状态；
- 对应数字化库；
- 正式模型文件记录。

模型文件记录遵循“模型运行定位、对应数字化库提供正式数据”的规则。若模型尚未形成对应数字化库，必须明确显示“尚未形成对应数字化库”，不得伪造库或记录。

## 5. 全部库

全部库列表展示全部有效数字化库。点击库后可查看：

- 库名称；
- 来源模型；
- 模型数字化编码；
- 当前状态；
- 文件记录；
- 字段设计；
- 数据权限。

库详情中可以显示来源模型，但不得另设“模型库关联查看”一级入口或独立分类入口。

## 6. 模型与库关系

1. 一模型一数字化库规则保持不变。
2. 模型详情可直接显示并跳转到其对应数字化库。
3. 库详情可直接显示其来源模型。
4. 模型和库的关系属于对象详情信息，不单独建设“模型库关联查看”页面。

## 7. 权限与数据源

1. 模型目录元数据用于模型库统一查看；不得因为模型不可人工发起而从“全部模型”中删除。
2. 数字化库正式记录仍执行原有本人/管理员权限边界。
3. 模型业务数据的正式来源仍是对应数字化库；模型库页面不得以 `model_runs.input_data/output_data` 代替正式业务数据。

## 8. 验收要求

至少验证：

- 顶部导航、驾驶舱常用服务、页面标题显示“模型库”；
- 页面存在且只以“全部模型 / 全部库”作为目录范围切换；
- 不出现“模型分类查看 / 库分类查看 / 模型库关联查看”入口；
- 全部模型直接来自系统模型目录，包含不可人工发起或尚无库的模型；
- 全部库包含全部有效数字化库；
- 模型详情可看到对应库与正式文件记录；
- 库详情仍能查看文件记录、字段和权限；
- 底层数字化库名称及“一模型一数字化库”规则不因前端名称调整而改变。
