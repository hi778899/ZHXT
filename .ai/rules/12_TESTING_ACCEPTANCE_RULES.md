# V17.7.19 当前增补——最终审批路径执行完整性验收

必须新增/保持以下回归场景：

1. 员工请休假形成 `部门经理 → 考勤主管` 的 `Path_final`；
2. 部门经理同意后审批运行仍为办理中，并产生考勤主管待办；
3. 此时不得写入“审批模型已正常归档”，不得提前启动智选；
4. 考勤主管完成后，审批模型才正常归档并立即触发智选；
5. 部门经理不同意且该意见配置为终止时，可以直接形成终止结果并归档、触发智选；
6. 任一行政/技术/业务审查子路径单独达到目标级次，不得被测试判定为整条审批完成；
7. 考勤主管必须由审批分管配置数字化库中的“业务审核岗”技术/业务审查分管 + 员工信息数字化库匹配形成，不得在审批代码中写死人名；
8. 技术/业务审查路径不得自动把行政负责人追加为审查节点；
9. 正常同意归档前必须验证 `已完成 step_index 集合` 覆盖本次 `Path_final` 全部必经节点。

# 12 测试与验收规则

## 1. 测试层级

至少覆盖：

- 单元测试
- API/服务测试
- 数据库 migration 测试
- 模型运行集成测试
- 审批集成测试
- 智选集成测试
- 关键 E2E
- 生产构建验证

## 2. 模型建设核心验收

必须验证：

1. 四阶段均可编辑并持久化；
2. 可从旧版本创建新草稿修改；
3. 发布后产生可运行模型；
4. 发布后建立对应数字化库；
5. 需要选择既有数据的字段能从指定数字化库动态加载；
6. 业务模型运行后正确写入本模型对应数字化库；
7. 入库后自动进入审批；
8. 审批完成后自动进入智选；
9. 智选按标识触发正确后续模型；
10. 全链路可通过“数字化编码 + 模型文件名 + 来源模型文件名”追溯；
11. 系统不得依赖模型 ID/实例 ID 识别模型或串联模型簇。

## 3. 回归测试

修改公共模型引擎、审批、智选、数据源或数字化配置时，必须回归至少一个既有已发布模型，防止平台改动导致历史模型失效。

## 4. 负面测试

必须考虑：

- 所引用数字化库不存在或不可用
- 标识无关联模型
- 审批不同意
- 重复提交
- 权限不足
- 数据源不可用
- migration 失败
- 模型版本不兼容
- 循环触发
- 重复定量触发

## 5. 验收证据

重要需求应保留测试日志、CI 结果、接口结果或界面截图，不能只以“开发人员说能用”作为验收依据。

## V17.7.11 文件名迁移验收

升级验收必须增加：旧格式文件名扫描结果为0（审计映射字段除外）；运行记录与数字化库文件名一致率100%；来源文件名无孤儿引用；业务→审批→智选链路能够使用新文件名完整追溯；待办、已办、办结和驾驶舱能够打开迁移后的既有记录；重复/冲突文件名为0。

## V17.7.14 数字化库模型运行来源验收

升级验收增加以下硬指标：

1. 正式数字化库记录 `run_id` 非空率为 100%（仅明确列入迁移异常且标记 `migration_pending` 的历史问题记录除外）；
2. 每个 `run_id` 均能关联真实 `model_runs`；
3. 数字化库 `file_name` 与对应 `model_runs.file_name` 一致率 100%；
4. 业务定义、员工、组织、模型时限、审批分管等基础/配置库同样满足上述要求；
5. 源代码除统一的模型归档/系统运行归档入口外，不得存在直接制造 `run_id=NULL` 正式记录的写库路径；
6. 页面不得出现 `std-*`、`src0622-*`、UUID 等技术键作为“文件名”；
7. 首次安装、旧库升级和系统源数据变更三种场景都要验证 `system_initialization/system_sync` 运行可追溯。


## V17.7.15 相对审批/审查级次验收

1. 任一来源模型不得把三级/四级/五级机构直接作为审批级次；
2. 发起人不计级次，第一个有效行政审批人必须显示为一级审批；
3. 技术审查、业务审查必须分别独立从一级开始编号；
4. 跨组织但未形成有效人员时不得增加审批/审查级次；
5. 阈值“增加一级”必须增加相对级次，不得直接修改绝对组织层级；
6. 发起人本人被匹配为审批/审查人时应跳过自审批；
7. 人员去重后各自路径级次必须连续；
8. 请休假案例至少验证：员工发起 → 一级审批（部门经理） → 一级业务审查（考勤主管） → 办结；
9. 至少再选两个非请休假模型验证同一规则，证明规则为全系统通用能力。


## V17.7.16 审批最终路径展示验收

1. 组织数字化库中的组织数字化属性必须参与审批/审查级次和人员匹配计算；
2. 普通审批界面不得显示基础审批目标、最终审批目标、技术/业务审查目标层级或级次、组织逐级路径、命中数字化标识阈值等中间运算数据；
3. 普通审批界面只能显示运算后的最终审批路径；
4. 最终审批路径节点必须按“岗位/角色名称（员工数字化编码）”显示；
5. 请休假示例应显示类似“部门经理（员工数字化编码）-考勤主管（员工数字化编码）”，不得同时出现一级审批、一级业务审查、五级机构/四级机构等中间说明；
6. 被隐藏的中间运算数据仍必须可在内部模型输出/数字化库审计字段中追溯，不得因界面精简而删除。
