# 26 审批/智选基础模型库运行入库规则

> 当前有效版本：V17.7.26

## 1. 总原则

审批模型、智选模型依赖的基础数据必须纳入“一模型一数字化库”治理。**基础数据完善必须通过运行模型形成真实运行，再完成数据入库**；不得把 seed、migration、运行时代码常量或人工 SQL 直接写入 `digital_library_records` 作为新的正式基础数据维护方式。

统一链路：

`发现基础数据缺失 → 定位对应数据产生模型 → 创建真实 model_runs → 生成统一模型文件名 → 模型运行形成结果 → 写入该模型唯一数字化库 → 基础库就绪校验 → 审批/智选继续运行`

## 2. 审批基础模型库

审批硬依赖至少包括：

- 模型数字化配置模型 → 模型数字化配置数字化库 `lib-standard-digital-config`
- 审批分管配置模型 → 审批分管配置数字化库 `lib-standard-approval-assignment`
- 员工信息模型 → 员工信息数字化库 `lib-standard-person`
- 组织名称数字化模型 → 组织名称数字化库 `lib-standard-dept`
- 组织关系模型 → 组织关系数字化库 `lib-digital-org-relationship-0622`
- 模型时限模型 → 模型时限数字化库 `lib-standard-model-timeout`
- 审批意见标准模型 → 审批意见数字化库 `lib-standard-approval-opinion`

审批支撑库包括业务分类、组织数字化、业务归属、员工数字化、阈值类属、审批阈值配置等对应模型·库。

## 3. 智选基础模型库

智选硬依赖至少包括：

- 模型数字化配置模型 → `lib-standard-digital-config`
- 标识关联配置模型 → `lib-standard-identifier-trigger`

数字化标识建设模型、模型信息标准模型等作为智选配置支撑模型库。

**标识关联配置数字化库允许 0 条关联数据**。0 条表示当前没有配置后续关联模型，是合法业务状态；不得为了通过完整性校验伪造关联数据。

## 4. system_initialization 最小启动闭环

`system_initialization` 仅允许用于首次建立审批模型能够启动所需的**最小基础闭环**，用于解决“基础配置自身要审批、审批又依赖基础配置”的循环依赖。

即使处于 `system_initialization`，也必须：

1. 运行对应数据产生模型；
2. 形成真实 `model_runs`；
3. 使用当前模型数字化编码和运行人员员工数字化编码形成统一模型文件名；
4. 再将结果归档进入该模型唯一数字化库；
5. 正式记录 `run_id` 不得为空。

最小闭环建立完成后，人工新增、修改基础配置必须恢复正常模型簇：

`基础配置模型 → 数字化库 → 审批模型 → 智选模型`

不得长期借用 `system_initialization` 绕过审批。

## 5. system_sync 边界

`system_sync` 只允许同步已经存在的系统事实或能够从现有正式数字化数据唯一推导的结果，例如员工账号对应员工编码、已发布模型的确定性模型数字化配置等。

如果业务分类、审批分管人员、技术/业务审查人、智选目标关系等**无法从现有正式数据唯一确定，则不得猜测、不得写死、不得自动编造**；必须记录基础模型库完整性问题，仅阻止受影响模型运行。

## 6. 禁止直接补库

新增代码、seed、migration 不得通过以下方式完善审批/智选正式基础数据：

`直接 INSERT digital_library_records`

也不得以 `UPDATE digital_library_records` 直接创造新的业务事实来替代模型运行。历史0622 migration 数据仅作为历史初始化来源，必须通过既有物化机制形成真实模型运行后继续使用。

## 7. 统一运行入库通道

系统基础数据自动初始化、同步、确定性补齐统一使用“模型运行入库”通道。该通道必须：

1. 由目标数字化库反查唯一数据产生模型；
2. 验证数据产生模型名称、已发布项目和当前19位模型数字化编码；
3. 创建真实模型运行；
4. `trigger_mode` 明确为 `system_initialization` 或 `system_sync`；
5. 正式数字化库记录写入真实 `run_id`；
6. 同一幂等键且数据未变化时不重复产生模型运行；
7. 数据变化时形成新的模型运行并更新当前正式记录。

## 8. 审批/智选就绪校验

审批模型当前结构计算前执行审批基础模型库就绪校验；智选模型当前结构计算前执行智选基础模型库就绪校验。

就绪检查至少包括：

- 数字化库存在且启用；
- 数字化库绑定的数据产生模型与本规则注册表一致；
- 数据产生模型存在已发布项目；
- 数据产生模型具有当前19位模型数字化编码；
- 要求非空的硬依赖具有正式数据；
- 正式数据不存在 `run_id IS NULL`；
- 标识关联配置数字化库按本规则允许0条数据。

错误必须指出“哪个基础模型 → 哪个数字化库 → 为什么未就绪”，不得只提示“未匹配到配置”。

## 9. 故障隔离

基础模型库完整性审计发现问题时：

- 记录审计问题；
- 阻止依赖该硬基础库的审批/智选运行；
- 不得因单个基础模型库缺陷使整个应用无法启动；
- 支撑库缺陷应记录并提示，不得自动猜测业务配置。
